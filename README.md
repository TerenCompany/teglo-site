# Teglo — лендинг, демо и бот-витрина

- `web/` — статический сайт: лендинг (`index.html`), интерактивное демо (`demo.html`), вау-сайт кофейни (`zerno-site.html`). Шрифты и three.js лежат локально (без Google Fonts и CDN), есть манифест веб-приложения.
- `bot/` — бот @tegloru_bot: показывает функции бота заведения (карта гостя, меню, живой статус заказа, игра, рассылка, отзыв, сводка владельцу) и принимает заявки. Заявку пересылает владельцу в Telegram и нигде не хранит.
- `deploy/` — установка на сервер и автообновление.

## Установка на сервер (один раз, под root)

```bash
curl -fsSL https://raw.githubusercontent.com/TerenCompany/teglo-site/main/deploy/setup.sh | bash
```

Скрипт спросит токен бота (ввод скрыт), Telegram ID для заявок и домен. Секреты хранятся только в `/opt/teglo/.env` на сервере (права 600), в репозиторий не попадают.

Как отдаётся сайт — скрипт решает сам:
- домена ещё нет → `http://IP:8088`;
- порты 80/443 свободны → свой Caddy с HTTPS;
- на сервере уже есть Caddy (системный или в Docker) → добавляет блок для домена в его Caddyfile (с резервной копией и проверкой, при ошибке откатывает).

Когда появится домен: A-запись `teglo.ru` и `www.teglo.ru` → IP сервера, затем запустить команду ещё раз.

## Обновление

Каждые 5 минут cron делает `git pull`; при изменениях статика обновляется сразу, бот пересобирается. Лог: `/var/log/teglo-update.log`.

## Ограничения

Персональные данные гостей здесь не собираются: демо на вымышленных данных, заявки — только то, что человек сам написал в Telegram. Реальная платформа с данными гостей — только на серверах в РФ (репозиторий TerenCompany/platforma).
